Why build it

为什么不直接买 SaaS

三个理由，决定了这套东西必须落在本机。

01

按分钟计费，长视频成本失控

数字人 SaaS 普遍按合成时长收费，一条十分钟的成片就要反复扣费；改一版文案、重录一句口播都得重新计费。本机推理的边际成本只有电费。

02

真人形象与声音必须留在本地

克隆素材是生物特征级数据。上传第三方平台意味着失去控制权，也无法向素材本人交代。整套模型、音视频与中间产物都只存在于本机磁盘。

03

批量出片要能整夜排队

真实场景是晚上丢进十条任务、第二天早上收片。所以队列必须支持断点续跑、暂停与取消，中途失败不能把已完成的部分全部作废。

Capabilities

六块能力，全部在本机跑完

从一段文案到一条带包装的成片，中间没有一步依赖外部服务。

双声音引擎

IndexTTS-2 / VoxCPM2 本地克隆，同一时刻只启一个；切换引擎时自动停旧进程再启新进程，避免两个模型同时占显存。

IndexTTS-2 · VoxCPM2

字幕逐字对齐

faster-whisper large-v3-turbo 先出词级时间戳，再与原始文案做 difflib 锚定，同音错字不会污染时间轴。实测 407 秒音频 29 秒对齐完。

词级时间戳 + difflib 锚定

口型同步

独立子进程跑口型模型，与主服务解耦；输入先压到 1920 长边控制显存与耗时，导出阶段再 lanczos 放大回 2K / 4K。

1920 长边 → lanczos 放大

智能 B-roll

用 CLIP 图像特征与 bge 中文文本向量做跨模态检索，按字幕时间轴自动匹配分镜素材，无需手工挑镜头。

Architecture

一条直线到底的数据流

浏览器只负责界面，server.py 负责一切调度，模型各自活在独立进程里。

为什么不用框架。安装包里的嵌入式 Python 只有标准库，目标机上没有 npm、也没有任何构建工具链。因此后端只用标准库，前端保持零构建步骤 —— 打开文件即运行，部署面最小。

为什么模型都在子进程。声音克隆与口型模型的依赖版本互相冲突，且崩溃会带走主进程。放进独立子进程后，主服务只通过文件与退出码通信，一个模型挂掉不影响队列整体。

为什么显存要串行。10GB 显存装不下两个模型同时驻留。声音合成结束后立刻释放，口型任务启动前按可配置阈值等待，宁可慢一点也不 OOM。

为什么产物直接落文件系统。中间产物写盘而不是走内存流，任务中断后可以按分段索引续跑；ffmpeg 只负责最后拼接与封装，不参与模型推理。

Engineering notes

工程难点与解法

六条真实的坑，每条按「现象 → 定位 → 解法」记录。这些都是单机推理与离线交付才会遇到的问题。

01

10GB 显存要同时喂声音模型和口型模型

现象
连续提交多个任务时随机 OOM，两个模型都想常驻显存。
定位
声音克隆与口型模型各自持有几百 MB 到数 GB 的显存，并发驻留直接超过 10GB 上限。
解法
改成严格串行：声音合成后立即释放显存；口型任务启动前按可配置阈值（默认 6500MB）轮询等待，阈值支持热更新，无需重启服务。
02

对齐子进程莫名卡死

现象
faster-whisper 对齐进程长时间无输出，父进程 wait() 永不返回，队列停在原地。
定位
子进程日志写满了 64KB 的管道缓冲区，父进程又在等它退出、没有读管道 —— 双方互等，典型死锁。
解法
子进程 stdout / stderr 一律重定向到日志文件，父进程改为轮询退出码并读文件排查，绝不用 PIPE 却不管它。
03

漏字的字幕块把时间轴压塌

现象
个别字幕块左右锚点零间隙，某个字符被拉到音频末尾，后面的字幕全部挤压重叠。
定位
当识别漏字导致锚点重合时，插值区间长度为 0，按比例分配时间戳就产生 t1 <= t0 的非法区间。
解法
在时间戳分配里加保底逻辑：检测到 t1 <= t0 时强制使用正向最小步长，保证时间轴单调递增。
04

pythonw 没有 stderr，队列 worker 裸死

现象
用 pythonw 启动后队列偶发假死：任务既没完成也没报错，界面一直转圈。
定位
无控制台意味着 stderr 不可用，未捕获异常让 worker 线程静默退出，主进程还活着等它。
解法
worker 外层加自动重启外壳；同时挂上 threading.excepthook，把未捕获异常落盘到 logs/server-error.log，事后可查。
05

目标机缺 VC++ 运行库，安装还被旧版挡住

现象
干净机器上嵌入式 Python 起不来，提示缺少运行库；想装官方运行库又被已存在的旧版本拦住。
定位
离线环境无法联网补依赖，系统级安装又受旧版本与权限约束，不适合让业务同事处理。
解法
提取所需 DLL 随安装包一起分发，装到 venv 里 python.exe 旁边 —— 应用级部署，完全不触碰系统目录。
06

OpenCV 5.x 删掉了 cv2.CascadeClassifier

现象
自动封面生成整段崩溃，报 AttributeError，但视频合成本身是成功的。
定位
OpenCV 5.x 移除了 cv2.CascadeClassifier，而封面逻辑依赖它做人脸定位。
解法
依赖钉死版本 4.12.0.88，并在离线组件包里锁定同一版本，避免环境漂移再次触发。
